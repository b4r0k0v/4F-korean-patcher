# 진여신전생 4F 한글 패처 개발 계획

구현 및 검증 현황은 [검증 기록](./verification.md)을 참고한다. 사용자 안내는 [사용 안내](./user-guide.md)에 정리했다. 아래 완료 기준 중 별도 PC 설치와 실제 게임 플레이 확인은 개발 PC의 파일 생성 검증과 구분한다.

## 1. 목표와 기준

- 요구사항은 아래 구현 범위·입력 규칙·사용자 흐름을 기준으로 한다.
- Windows 전용 Rust + Tauri 데스크톱 앱을 만든다.
- 사용자가 원본 파일, 한글 패치 압축파일, 외부 도구, 작업·출력 폴더를 지정하면 한 번의 실행으로 패치를 완료한다.
- 화면은 단순하게 유지하고, 진행 상황과 실패 원인을 한국어로 설명한다. 상세 오류 trace는 복사할 수 있게 한다.
- 현재 저장소에는 앱 구현이 없으므로 프로젝트 초기화부터 진행한다.

## 2. 구현 범위와 입력 규칙

| 항목 | 필수 여부 | 처리 규칙 |
| --- | --- | --- |
| 본편 원본 | 필수 | 북미/UNDUB/DECRYPTED 3DS, 지정 SHA-256과 일치해야 진행 |
| 본편 1차 패치 | 필수 | ZIP 루트 전체 내용을 적용. `ExeFS`·`RomFS`는 도구의 추출 폴더명에 맞춰 병합 |
| 본편 2차 패치 | 필수 | ZIP 루트의 `patch/` 안 내용을 본편 추출 폴더에 덮어쓰기 |
| DLC 원본 | 선택 | UNDECRYPTED CIA, 지정 SHA-256과 일치해야 진행 |
| DLC 패치 | DLC 선택 시 필수 | ZIP 루트의 `patch/` 안 내용을 DLC 추출 폴더에 덮어쓰기 |
| 외부 도구 경로 | 필수 | Decryptor와 포크 HackingToolkit3DS의 압축 해제 위치 지정 |
| 작업 폴더 | 필수 | 실행마다 전용 임시 하위 폴더 생성 |
| 출력 폴더 | 필수 | 최종 결과 저장 |
| 본편 출력 형식 | 필수 | CIA 또는 3DS |
| DLC 출력 형식 | 고정 | CIA |

SHA-256 기준값:

```text
본편: 5FDBC59C52BC2747488C21502E0BBCD67910A557640ADEEF878C19328EF20168
DLC:  A18A1C190301F204602395B415BF37B2B4BDCD5C05709BBCD46EF7316936DB93
```

- 본편과 DLC 원본만 해시를 검증한다. 패치 압축파일과 외부 도구에는 해시 검증을 추가하지 않는다.
- DLC를 선택하지 않으면 DLC 관련 단계를 모두 건너뛴다. DLC 패치만 선택한 상태는 실행할 수 없다.
- 외부 도구는 앱에 포함하거나 자동 다운로드하지 않는다. 다운로드 링크와 경로 선택 기능을 제공한다.
- 두 도구의 다운로드 주소는 확정되어 있으며, 기준 문서에 적힌 주소를 그대로 사용한다.
  - [Batch CIA 3DS Decryptor](https://gbatemp.net/download/batch-cia-3ds-decryptor.35098/download?version=35152)
  - [포크 버전 HackingToolkit3DS](https://github.com/b4r0k0v/HackingToolkit3DS/releases/download/v9/HackingToolkit3DSv9.zip)
- 원본과 패치 입력 파일은 수정하지 않는다. 도구에는 작업 폴더에 복사한 파일을 전달한다.
- 패치 압축 형식은 `.zip`만 지원한다. 1차 본편 패치는 ZIP 루트, 2차 본편·DLC 패치는 ZIP 루트의 `patch/`를 적용 기준으로 고정한다. 임의의 최상위 폴더를 자동 탐색하지 않는다.

## 3. 도구 조사 결과와 연동 방침

`dev-temp`의 실제 배치 파일 및 ZIP 엔트리를 읽어 진입점과 처리 규칙을 확인했다. 상세 근거와 호출 규약은 [tool-integration.md](./tool-integration.md)에 정리한다. 도구를 실행한 통합 검증은 아직 수행하지 않았다.

- Decryptor: `Batch CIA 3DS Decryptor.bat`는 파일 인자 없이 현재 폴더의 CIA/3DS를 처리한다. DLC 입력을 `dlc.cia`로 준비하면 예상 결과는 `dlc (DLC)-decrypted.cia`다. 마지막 `pause`를 처리하고 `log.txt`와 결과 파일을 확인해야 한다.
- HackingToolkit3DS: 메뉴 진입점은 `HackingToolkit3DS.bat`이며, 자동화에 참고할 인자형 배치는 `Unpack3DSYes/No.bat`, `UnpackCIAYes/No.bat`, `Repack3DS.bat`, `RepackCIA.bat`다.
- 추출 배치는 `<입력 파일명.확장자>_Unpacked/`를 생성한다. 본편 1차 ZIP의 `ExeFS/`, `RomFS/`는 각각 `ExtractedExeFS/`, `ExtractedRomFS/`로 매핑해서 덮어쓴다. 2차 본편과 DLC는 `patch/` 내부 상대 경로를 그대로 적용한다.
- 배치의 출력 억제, 실행 파일명 불일치, 고정 경로와 DLC 콘텐츠 누락을 해결하기 위해, Rust 어댑터에서 배치에 명시된 하위 실행 파일을 직접 호출하는 방식을 기본으로 한다. 기존 도구 폴더나 배치 파일은 수정하지 않는다.
- 본편 CIA 재생성은 3DS 추출 디렉터리를 명시적으로 입력받도록 구현한다. 기존 `RepackCIA.bat`는 `.cia_Unpacked` 경로를 전제로 하므로 3DS 추출 결과에 그대로 호출하지 않는다.
- DLC는 전체 콘텐츠 인덱스와 ID를 보존하는 전용 재생성 경로를 구현한다. 콘텐츠 0~2만 다루는 기본 CIA 배치를 그대로 사용하지 않는다.
- 본편 `code.bin` 압축 해제 여부, DLC 전체 콘텐츠 추출·재생성의 실제 호환성, 처리 용량·시간은 실파일 통합 검증에서 확인한다. 이 항목들은 다운로드 주소나 ZIP 구조의 미정 사항과 구분한다.

## 4. 구조 제안

- 프런트엔드: Tauri + TypeScript 기반의 단순한 폼 UI. 초기안은 복잡한 상태 관리 프레임워크 없이 구성한다.
- Rust 백엔드: 입력 검증, 스트리밍 SHA-256 계산, 압축 해제, 파일 덮어쓰기, 외부 프로세스 실행, 결과 저장과 정리를 담당한다.
- UI는 실행 요청과 취소 요청을 전달하고, 백엔드의 상태 이벤트를 받아 표시한다. 파일 처리와 도구 실행은 Rust에 둔다.
- 해시 계산과 패치 작업은 UI를 막지 않는 작업으로 실행한다. 동시에 실행 가능한 패치 작업은 하나로 제한한다.
- 도구 실행 규약을 어댑터로 분리해 도구 변경이 패치 순서와 UI 전체에 전파되지 않게 한다.

예상 파일 구성:

```text
docs/development-plan.md
docs/tool-integration.md
src/                          # 화면, 입력 상태, 진행·오류 표시
src-tauri/src/commands.rs      # UI 호출 진입점
src-tauri/src/model.rs         # 요청, 상태, 단계, 결과 모델
src-tauri/src/validation.rs    # 경로·입력 조합 검증
src-tauri/src/hash.rs          # SHA-256 검증
src-tauri/src/archive.rs       # 압축 구조 검증과 안전한 해제
src-tauri/src/workspace.rs     # 실행별 임시 폴더와 정리
src-tauri/src/tools/           # Decryptor, HackingToolkit3DS 어댑터
src-tauri/src/pipeline.rs       # 패치 단계 실행과 취소
src-tauri/src/error.rs         # 사용자 안내와 상세 진단 정보
```

## 5. 화면과 사용자 흐름

1. **도구 설정**: 두 도구의 다운로드 링크, 압축 해제 안내, 경로 선택, 사용 가능 여부를 표시한다. 경로는 로컬 설정에 저장하고 다음 실행 때 다시 확인한다.
2. **파일 선택**: 본편과 두 패치를 선택한다. DLC 사용을 켜면 DLC 원본과 패치를 함께 받는다. 원본 선택 후 해시 검사 상태를 표시한다.
3. **출력 설정**: 작업 폴더, 출력 폴더, 본편 CIA/3DS 형식을 선택한다.
4. **실행**: 검증된 입력이 모두 준비되면 `패치하기`를 활성화한다. 실행 중에는 입력 변경과 중복 실행을 막는다.
5. **진행**: 현재 단계, 완료 단계 수, 로그 요약, 취소 버튼을 표시한다. 도구가 진행률을 제공하지 않으면 해당 단계는 진행 중 표시를 사용한다.
6. **결과**: 성공 시 결과 파일 경로와 출력 폴더 열기를 제공한다. 실패·취소 시 원인, 해결 방법, 보존된 작업 폴더 경로와 상세 오류 복사를 제공한다.

파일 선택이 바뀌면 해당 해시 검증 상태를 무효화한다. 실행 전에도 검증 이후 파일 변경 여부를 확인하며, 변경되었으면 다시 검사한다.

## 6. 패치 실행 순서

| 순서 | 단계 | 완료 조건 |
| --- | --- | --- |
| 1 | 입력·도구·경로 사전 검사 | 필수 입력과 해시 일치, 파일 접근 및 폴더 쓰기 가능 확인 |
| 2 | 전용 임시 폴더 생성, 입력 복사 | 실행 ID와 작업 소유 표시를 기록하고 도구용 입력 준비 |
| 3 | 선택한 DLC 해독 | Decryptor 실행과 해독 결과 확인 |
| 4 | 본편 추출 | HackingToolkit3DS 실행과 추출 구조 확인 |
| 5 | 본편 1차 패치 적용 | ZIP 루트 전체 내용을 적용하고 ExeFS/RomFS 폴더명 매핑 완료 |
| 6 | 본편 2차 패치 적용 | `patch` 내부 내용 덮어쓰기 완료 |
| 7 | 선택한 DLC 추출 | 해독된 DLC 추출 결과 확인 |
| 8 | 선택한 DLC 패치 적용 | `patch` 내부 내용 덮어쓰기 완료 |
| 9 | 본편 재생성 | 선택한 CIA/3DS 결과 생성 확인 |
| 10 | 선택한 DLC 재생성 | CIA 결과 생성 확인 |
| 11 | 출력 폴더에 결과 저장 | 선택한 모든 결과의 저장 완료 확인 |
| 12 | 임시 폴더 정리, 결과 안내 | 해당 실행의 임시 하위 폴더만 삭제 |

- 외부 도구는 종료 코드뿐 아니라 예상 결과물의 존재, 크기, 도구별 구조 조건으로 성공 여부를 판정한다. 구체적인 조건은 실제 도구 조사 후 확정한다.
- 후속 단계는 앞 단계가 성공한 경우에만 시작한다. 실패 후 자동 재시도나 중간 단계 재개는 초기 범위에 포함하지 않는다.
- 결과는 작업 폴더에서 모두 생성한 뒤 출력 폴더의 임시 이름으로 복사하고, 복사 검증 후 최종 이름으로 확정한다. 서로 다른 드라이브도 지원한다.
- 출력 이름은 실행 ID 등을 포함해 충돌을 피하고, 기존 파일을 덮어쓰지 않는다. 일부 결과만 저장된 실패는 저장된 파일과 미완료 항목을 구분해 알린다.
- 결과 생성 검증과 실제 게임 실행 검증을 구분한다. 파일 생성만으로 게임 내 정상 동작을 보장했다고 표시하지 않는다.

## 7. 파일 관리, 취소, 오류 처리

- 작업 폴더 아래에 실행별로 고유한 디렉터리를 생성한다. 본편, DLC, 패치 해제, 로그, 임시 결과를 분리한다.
- 자동 삭제 전 경로와 소유 표시를 확인한다. 삭제 대상은 해당 실행이 만든 임시 하위 폴더로 제한하며, 입력이나 출력이 그 안에 위치하는 구성은 거부한다.
- 압축 항목의 절대 경로, 상위 경로 이동, 링크 등을 통한 작업 영역 밖 쓰기를 차단한다. 필수 `patch` 폴더가 없으면 적용 전에 실패 처리한다.
- 공백·한글 경로를 포함한 Windows 경로 처리를 검증한다. 도구가 지원하지 않는 경로 조건은 실행 전에 안내하거나 전용 작업 경로에서 처리한다.
- 도구는 필요한 작업 디렉터리와 인자를 명시해 실행하고, 표준출력·표준오류·종료 코드를 기록한다. 배치 도구를 사용할 경우 셸 특수문자가 포함된 경로도 검증한다.
- 취소 시 새 단계를 시작하지 않고 실행 중인 도구와 자식 프로세스가 종료되었는지 확인한다. 내부 복사·해시 작업도 취소 신호를 확인한다.
- 취소·실패 시 작업 폴더와 진단 자료를 보존한다. 앱 종료 요청은 실행 중임을 안내하고, 종료를 진행하면 취소 절차를 수행한다.
- 성공 후 임시 폴더 정리만 실패한 경우에는 결과물 생성 성공과 정리 실패를 구분하고, 남은 경로를 안내한다.
- 오류에는 실행 ID, 실패 단계, 원인, 도구 종료 코드, 상세 로그와 작업 폴더 경로를 연결한다. 화면에는 쉬운 설명을 우선 표시하고 상세 trace를 복사할 수 있게 한다.

## 8. 단계별 개발과 완료 기준

### 1단계: 도구 조사와 프로젝트 초기화

- 조사한 실행 규약을 바탕으로 하위 실행 파일 직접 호출 어댑터를 설계한다. ZIP 전용 입력과 확정된 내부 구조를 사용한다.
- Tauri/Rust/TypeScript 프로젝트, 개발 실행 명령, Windows 빌드 설정을 구성한다.
- 완료 기준: 빈 앱이 실행·빌드되고, 도구별 호출·입출력 규칙과 실파일 검증 항목이 구현에 연결된다.

### 2단계: 입력 화면과 사전 검증

- 경로 선택, DLC 선택, 출력 형식, 도구 다운로드 안내와 설정 저장을 구현한다.
- 원본 스트리밍 해시 검사와 입력 조합·경로 검증을 구현한다.
- 완료 기준: 올바른 입력으로만 실행 가능하며, 오류 원인을 해당 입력 근처에서 이해할 수 있다.

### 3단계: 작업 엔진과 본편 패치

- 전용 작업 폴더, 안전한 압축 해제와 덮어쓰기, 도구 실행 어댑터를 구현한다.
- 본편 추출 → 1차 패치 → 2차 패치 → CIA/3DS 재생성을 연결한다.
- 완료 기준: 본편만 선택한 경우 두 출력 형식이 각각 생성되고 원본이 보존된다.

### 4단계: DLC와 결과 저장

- DLC 해독·추출·패치·CIA 재생성을 추가한다.
- 전체 결과 저장, 충돌 방지, 성공 시 정리와 실패 시 보존을 연결한다.
- 완료 기준: 본편+DLC 전체 흐름이 성공하고, 중간 실패 시 성공으로 오인하지 않는다.

### 5단계: 진행 안내와 복구 정보

- 단계별 이벤트, 취소, 실행 중 종료 처리, 친절한 오류와 trace 복사를 구현한다.
- 완료 기준: UI가 멈추지 않고, 실패·취소 후 단계와 작업 경로를 확인할 수 있으며 도구가 남아 실행되지 않는다.

### 6단계: Windows 검증과 배포 준비

- 아래 검증 항목을 수행하고 설치 패키지를 생성한다.
- 사용자 안내에 준비물, 포크 도구 링크, 실행 절차, 오류 자료 복사 방법을 포함한다.
- 완료 기준: 개발 환경 밖의 Windows 환경에서 설치부터 결과 생성까지 확인하고, 도구 실행 규약에 따른 연동 검증을 완료한다.

## 9. 검증 계획

자동 검증은 데이터 손상이나 잘못된 성공 판정을 막는 핵심 로직에 집중한다.

- **입력 검증**: 본편/DLC 해시 일치·불일치, 검사 후 파일 변경, DLC 입력 누락, 읽기·쓰기 불가 경로.
- **파일 처리**: ZIP 전용 입력, 1차 루트의 ExeFS/RomFS 매핑 후 2차 `patch` 적용 순서, DLC `patch` 적용, 필수 폴더 누락, 압축 경로 탈출 차단.
- **도구 연동**: 실제 존재하는 32/64비트 실행 파일 선택, 본편 3DS 추출 결과의 CIA 변환, DLC 콘텐츠 전체 보존, 도구 오류 로그 수집.
- **작업 폴더**: 성공 시 해당 실행 폴더만 삭제, 실패·취소 시 보존, 상위 폴더·원본·기존 출력 보존.
- **파이프라인**: 테스트용 도구 실행기를 이용해 비정상 종료, 결과 누락, 취소, 일부 출력 저장 실패를 재현하고 후속 단계 중단 확인.
- **Windows 수동 검증**: 공백·한글·셸 특수문자 경로, 서로 다른 드라이브, 디스크 공간 부족, 파일 잠김, 실행 중 앱 종료.
- **실파일 통합 검증**: 본편만/CIA, 본편만/3DS, 본편+DLC/CIA, 본편+DLC/3DS 네 조합을 확인하고, 사용자가 준비한 실행 환경에서 결과 동작을 확인한다.
- 게임 원본과 패치 실파일은 저장소나 자동화 테스트 데이터에 포함하지 않는다. 자동 테스트에는 직접 만든 작은 샘플을 사용한다.
- Rust 포맷·정적 검사·핵심 테스트와 프런트엔드 타입 검사·프로덕션 빌드를 수행한다.

## 10. 초기 범위 밖의 기능

- 외부 도구 번들링 및 자동 다운로드·설치
- 패치 압축파일과 도구의 해시 검증
- 실패 작업의 자동 재개 및 앱 자동 업데이트
- macOS/Linux 지원과 복수 작업 동시 실행

위 기능은 필수 흐름이 검증된 이후 필요에 따라 별도로 계획한다.
